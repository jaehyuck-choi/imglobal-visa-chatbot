# iM Global — 외국인 체류기간 연장 안내 챗봇

> **2026 AI Blockchain Challenge in Daegu** 출품작 "iM Global — 외국인 고객을 위한 금융 특화
> 번역·체류 안내 플랫폼"(과제명 **TCB: Translation·Chatbot·Blockchain**, 팀 **아이엠그라운드**)
> 중, **제가(최재혁, 통계학과) 직접 설계·개발한 "체류기간 연장 안내 챗봇" 파트**를 정리한
> 저장소입니다. 팀의 다른 파트(금융 특화 번역모델, 블록체인 신뢰 계층 설계)는 이 저장소의
> 범위 밖이며, 아래 "전체 서비스에서 이 저장소의 위치" 절에서 맥락만 간단히 설명합니다.

- 챗봇 파트 단독 데모(이 저장소, GitHub Pages): https://jaehyuck-choi.github.io/imglobal-visa-chatbot/
- 배포 데모(팀 서비스 전체): https://imglobal.vercel.app/
- 시연 영상: https://youtu.be/fduzuZpGduY
- 결과: 수상하지 못함 — 이 저장소는 결과보다 **문제를 푼 방식과 디버깅 과정**을 보여주는 데
  목적이 있습니다.

## 출발점 — 사용자 관점

주짓수 도장에서 만난 외국인 친구들이 체류 연장 같은 한국 행정절차를 저에게 자주 물어봤습니다.
이들은 **어떤 서류가 필요한지는 대부분 알고 있었지만, 그 서류를 어디서 어떻게 받는지를 몰라서**
막혔습니다. 그래서 이 챗봇은 서류 목록에서 멈추지 않고 다음 두 가지를 중심으로 설계했습니다.

- **서류마다 발급 방법까지 안내**: 대학 포털, 은행 앱·창구, 고용주, 하이코리아 서식 등 발급
  경로와 대안, 유효기간 주의사항을 서류별로 정리했습니다
  (`visa_extension_chatbot_final.json`의 `how_to_obtain`·`obtain_type`·`fallback` 필드).
- **마지막 정리 화면을 토글로**: 대화 끝에 결과가 한꺼번에 길게 나오면 읽기 싫고 눈에도 잘
  들어오지 않아서, 결과를 항목별 펼침/접힘 토글로 바꿨습니다
  (`chatbot/visa_chatbot_combined.html`).
- **'모르겠어요'로도 끊기지 않는 대화**: 외국인은 본인 상황을 정확히 모를 수 있다는 전제로, 주요
  질문마다 '모르겠어요' 선택지를 두고 그 경우에도 다음 행동을 안내합니다.
- **막다른 길 없는 예외 처리**: 경로가 불확실한 경우(구직등록 90일 초과, 사업장 변경 횟수 소진 등)에도
  관할청 연락처와 하이코리아 대표번호(1345, 다국어 상담)까지 안내합니다.

## 틀린 정보를 주지 않기 위한 설계 원칙

- **수수료 금액 비공개**: 금액은 바뀌면 바로 오정보가 되므로, 수수료가 있다는 사실과 납부 방법만 안내.
- **공식 서식은 원본 링크로**: 신청서는 자체 사본 대신 국가법령정보센터(law.go.kr) 원본으로 연결하고,
  하이코리아 온라인 신청 채널도 함께 안내.
- **대학 등급 규칙은 보수적으로**: 대학 등급별 서류 면제·심사 강화는 챗봇이 확정 판정하지 않고
  일반 기준만 정확히 안내.
- **명칭 정리**: E-9 "구직등록 특례"를 의미가 드러나는 "구직신청자 대상 특례"로 확정(2026-09-18).

## 품질 관리 — 화면 문구와 데이터의 일치

- 대화 흐름은 `visa_extension_chatbot_final.json` 하나로 관리(v1→v5.0, "UI/UX 팀 전달용" 최종본)하고,
  통합 데모 HTML은 이 JSON을 읽어 생성.
- Playwright로 전체 대화 경로를 끝까지 눌러보는 end-to-end 테스트를 통과시킴.
- 문구 검수용 엑셀은 JSON에서 옮겨 적지 않고, **실제 챗봇 화면을 자동 순회하며 노출된 문구만 긁어와**
  생성. 검수 결과는 JSON과 HTML 양쪽에 동시에 반영해 엑셀·JSON·HTML 간 불일치를 막음. 한쪽만
  수정돼 불일치가 생긴 적이 한 번 있었고, 자체 점검으로 발견해 수정.
- 생성·테스트·검수 스크립트는 작업 당시 웹 세션 환경에서만 실행되어 이 저장소에는 포함되어 있지
  않습니다.

## ① PDF 구조화 추출 — `D2.py`, `extract_e9_stay_extension.py`

PDF에서 텍스트만 뽑는 게 아니라, **원문의 레이아웃 좌표를 근거로 문서 구조 자체를 복원**합니다.

- `pypdf`의 북마크(outline)로 D-2/E-9 챕터의 정확한 페이지 범위를 자동으로 찾음 (하드코딩 대신,
  문서 개정에도 재사용 가능하게 설계).
- `pdfplumber`로 단어 단위 좌표(x0, top)를 뽑아, 좌측 라벨 컬럼·목차 바로가기·쪽번호 같은
  페이지 부속 요소를 제거하고, **좌측 라벨이 바뀌는 지점(top 좌표)을 추적**해 "체류기간연장허가"
  라벨이 적용되는 본문 영역만 정확히 스코프를 잘라냄.
- 숫자+단위가 낱글자 단위로 쪼개져 추출되는 PDF 특성을 고려해, 단어 사이 간격이 실제 띄어쓰기인지
  판별 후 재조합.
- 줄의 선행 마커(가./나./다., ❍, -, ※, * 등)와 들여쓰기(x0)로 계층 깊이를 판정, 스택 기반으로
  트리 구조를 구성.
- **D-2와 E-9의 서로 다른 문서 구조를 직접 발견하고 해결**: D-2는 라벨이 매 페이지 반복
  인쇄되지만, E-9은 섹션이 두 페이지에 걸쳐 이어지며 두 번째 페이지에는 라벨이 다시 찍히지
  않음 → 라벨 상태를 페이지 경계 너머로 이월시키는 `extract_scoped_lines_v2()`를 작성. 또한
  D-2는 최상위 항목이 "가·나·다"인데 E-9은 "1·2·3"이 최상위이고 "가·나·다"가 그 하위 항목인
  역전된 위계 구조라, 분류 로직을 확장해 두 체계를 모두 올바르게 인식하도록 처리.

## ② 2차 가공 및 DB화 — `build_stage2.py`, `build_sqlite.py`

- `build_stage2.py`: 1차 구조화 결과(원문 그대로의 트리)를 챗봇 로직이 바로 쓸 수 있는 형태로
  재가공.
- `build_sqlite.py`: 표로 관리하기 자연스러운 데이터(관할청·지역·세부전공·서류)는 실제 SQL
  테이블로 정규화해 WHERE/JOIN이 가능하게 하고, 규칙마다 필드 구성이 다른 "자격 조건
  (eligibility_rules)"은 고정 컬럼에 억지로 맞추지 않고 유연한 구조로 저장 — **데이터 특성에
  따라 정규화 수준을 다르게 설계**한 부분.
- `view_d2_db.ipynb`: 빌드된 DB를 검증용으로 조회하는 노트북.

## ③ 지역·관할청 매핑 — `full_region_list.py`, `build_offices_json.py`, `office_lookup.py`

- `full_region_list.py`: 전국 **시/도 + 시/군/구 228개** 전체 목록을 직접 구축. 2026.07
  전남광주통합특별시 출범, 2023 군위군 경북→대구 편입 등 **최신 행정구역 개편을 웹 검색으로
  교차검증**해 반영. "공식 코드표(행정표준코드관리시스템) 재대조 필요"라는 한계를 코드 주석에
  그대로 남겨둠.
- `build_offices_json.py`: 공공데이터포털 API로 받은 전국 출입국·외국인관서 54개 현황을
  정리하는 과정에서, **원본 데이터 자체의 오류를 발견하고 수정**: 광주출입국·외국인사무소
  목포출장소의 "관할구역" 필드가 "목포군"으로 잘못 기재되어 있었는데(목포는 1949년 이후 줄곧
  '시'), 같은 레코드의 "주소" 필드는 "목포시"로 올바르게 적혀 있다는 점을 근거로 원본 API의
  오기로 판단하고 수정 — 고치지 않으면 사용자가 정확한 행정구역명을 입력해도 조용히 다른
  사무소로 잘못 매칭되는, 겉으로는 드러나지 않는 실패였음.
- `office_lookup.py`: 관할구역 자유서식 텍스트에서 "(김해시, 밀양시, 양산시 제외)" 같은
  제외조건을 정확히 파싱. 단순 문자열 포함검사로는 제외 대상 도시가 오히려 그 사무소 관할로
  오탐되는 문제, 그리고 레코드마다 시/도 신·구 명칭이 혼재(강원특별자치도 vs 강원도)해 매칭이
  실패하던 문제를 **사용자 리포트를 받아 재현하고 수정**한 이력이 코드에 남아 있음.
- 이후 `visa_extension_chatbot_final.json` v3에서는 주소 재입력 UI를 자유 텍스트에서 228개
  드롭다운 방식으로 바꾸면서, 런타임 퍼지 매칭 자체가 불필요해져 로직을 단순화함.

## ④ 챗봇 대화 흐름 — `visa_extension_chatbot_final.json`, `d2_chatbot_demo_2.html`

- D-2(유학)·E-9(비전문취업) 체류기간 연장 안내를 하나의 공통 프로세스 골격으로 설계:
  로그인 시 체류지 주소 자동 확인 → 현재 상황 분기(계속 근무/구직중/휴학 등) → 조건별 세부
  질문(3년 만기 재고용 여부, 구직등록 90일 이내 여부, 야간/주말 수업 여부 등) → 등록 주소 기반
  관할청 자동 매칭 → 진행 경로별 준비서류 + 관할기관 정보를 한 화면에 제공.
- 질문마다 "모름" 선택지를 넣어 챗봇 이탈을 줄이는 UX 설계.
- **버전 이력(v1→v5)을 직접 관리하며 실제 버그를 수정**: E-9에 주소확인·관할청 매칭 단계
  자체가 없었던 구조적 공백을 D-2와 통합해 해소, E-9 "재고용확인서" 질문에서 '아니오' 응답이
  자격 게이트처럼 처리돼 폴백으로 잘못 빠지던 라우팅 버그 수정, 수수료는 실제 금액을 화면에
  노출하지 않기로 정책 확정 등.
- `visa_chatbot_combined.html` (최종본, Pages 첫 화면): D-2·E-9를 하나로 합친 챗봇. 마지막
  "정리해드릴게요" 단계에서 서류·관할기관 등 결과를 항목별 토글(펼침/접힘)로 보여주도록 UI 개선.
- `d2_chatbot_demo_2.html`: 위 로직을 실제 체험할 수 있는 단일 HTML 데모. 라이트/다크 모드
  대응, 대화창과 함께 내부 로직 추적(trace) 패널을 보여줘 "왜 이 질문을, 왜 이 서류가 나왔는지"를
  바로 확인할 수 있게 설계.

## 실행 방법

```bash
pip install -r requirements.txt
```

- 각 스크립트는 입출력 경로를 `../data/` 같은 상대경로로 쓰므로, **스크립트가 있는 폴더로 이동한 뒤
  실행**합니다 (예: `cd extraction && python D2.py`).
- `extraction/*.py`는 원본 PDF(`docs/260901_체류민원_자격별_안내_매뉴얼.pdf`)가 있어야 실행됩니다.
  원본 PDF는 저작권 문제로 포함하지 않았으므로, 법무부에서 같은 이름으로 받아 `docs/`에 두면 됩니다.
- `processing/build_stage2.py`는 `data/process_overview_easylaw.json`(easylaw.go.kr의
  체류기간연장허가 공통 절차 정리본)을 입력으로 쓰는데, 이 파일은 작업 당시 임시 파일로만 존재해
  보존되지 않았습니다. 따라서 이 스크립트는 그대로는 재실행되지 않으며, 산출물인
  `data/D2_stay_extension_stage2.json`만 저장소에 포함되어 있습니다.
- `processing/build_sqlite.py`는 저장소에 있는 파일만으로 `data/d2_chatbot.db`를 다시 만들 수 있습니다.
- `chatbot/`의 HTML 파일들은 데이터가 파일 안에 내장된 단일 HTML이라, 브라우저로 바로 열면 됩니다.

## 한계 / 다음 단계

- 데모 단계로, 실제 은행 시스템(계좌·KYC)과는 연동되어 있지 않습니다.
- `full_region_list.py`의 228개 지역 목록은 사람의 지식 + 부분 웹 검증으로 만든 것으로,
  실제 서비스 투입 전에는 공식 코드표(행정표준코드관리시스템)로 전수 재대조가 필요합니다.
- 공공데이터 API 스냅샷(2026-09-15 조회)은 시간이 지나면 관할구역이 바뀔 수 있어, 주기적
  재조회·diff가 필요합니다.
- **다국어 미지원**: 정작 E-9·D-2 대상자는 한국어가 서툰 경우가 많은데 챗봇은 한국어 전용입니다.
  팀의 금융 특화 번역 모듈과 연결하는 것이 다음 과제입니다.
- **은행 데이터 연동**: 급여 입금 내역 등(마이데이터)으로 재직 여부를 미리 파악하면 질문 수를 줄일 수
  있습니다.
- **선제적 알림**: 사용자가 챗봇을 열어야 시작되는 구조에서, 만료가 다가오면 은행 앱이 먼저 알려주는
  구조로 바꾸는 것이 목표입니다.
- 팀의 번역모델(NLLB-200+LoRA 금융특화 번역)·블록체인 신뢰 계층 설계는 다른 팀원 담당으로
  이 저장소 범위 밖입니다.
